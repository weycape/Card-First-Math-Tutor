# 错题本系统（Mistake Pattern Tracker）

> 提炼自真实一对一辅导实践：常错点库的建档、计数、销号与复发加深机制。
> **不含任何真实聊天记录、学生个人信息**——只有可复用的方法。

给"一做就错"型学习者用的错题管理系统。目标不是把错题抄一遍，而是把重复犯的错变成"已改正"。
适用于任何需要动手练习的学科（编程、数学、语言等）。

## 定位

- **管"重复犯的错"**：偶发一次的失误不建档，成模式才编号。
- **不代替讲课**：它是练习–批改循环的记账本，配合正常教学使用。
- **学生无感**：建档计数是老师后台做的事，不给学生增加负担。

## 核心机制

### 1. 编号建档

每个常错点一个编号（P1、P2……），建档字段：

| 字段 | 说明 |
|------|------|
| 错因模式 | 一句话说清错在哪（如"`==` 写成 `=`"） |
| 典型样子 | 贴一行真实错例代码/写法 |
| 首次出现 | 哪道题、哪天 |
| 出现次数 | 累计命中次数 |
| 连续未出现 | 连续多少次练习没再犯 |
| 状态 | `出题池`（还在犯）/ `已改正`（销号） |

### 2. 计数规则（每次批改后更新）

- 同一错因**重复出现** → 出现次数 +1，连续未出现清零。
- 本次**未出现** → 连续未出现 +1。
- **偶发不编号**：以前做对过、这次偶然写错，且能立刻自己改对的，记一笔但不建档。

### 3. 销号与复发

- **销号**：连续两次练习未出现 → 移出出题池，状态记"已改正"。不删除档案，留着备查。
- **复发**：已改正的错因再次出现 → 打回出题池，连续未出现清零，出现次数继续累加。
- **复发加深**：同一个错因第三次及以上出现，变式题加深一层（见下）。

### 4. 变式题规则

每次练习后只出一道变式题，专打本次**仍在犯**的错因：

- 已连续两次改正的不再出。
- 同一道没过，**不叠题**——继续改同一道，不另起新题。
- 重复犯的加深一层：第一次是原样复现，第二次换场景/加条件，第三次要求讲出为什么。
- 本次无仍在犯错因 → 不出题，直接过。

### 5. 批改结构

1. **先给明确结论**：对 / 错，一句话。
2. **先肯定对的地方**：具体指出哪行写得好。
3. **编号指出错误**：错误行定位 + 对应常错点编号（如"第 9 行，P10 复发"）。
4. 新错因当场编号建档，老错因更新计数。

### 6. 定期复习

- 每学完几节，**快速过一遍出题池**：把还在犯的错因列出来，防止旧错复发。
- 讲新课前，先看一眼出题池——新课里可能踩到的旧坑，提前点一句。

### 7. 判分记录

每次练习追加一条，不散记：

```text
日期｜题目｜结论（通过/首个报错行）｜命中错因编号｜变式题是什么
```

## 不要做的事

- 不要把真实聊天记录、学生个人信息放进 skill 或示例。
- 不要给偶发失误建档——建档的是"模式"，不是"失手"。
- 不要一次出多道变式题；不要在旧题没过时叠新题。
- 不要把"已改正"的档案删掉——复发时要查历史。
- 不要只记错题不记"连续未出现"——销号依据的是持续不犯，不是时间过去了。
